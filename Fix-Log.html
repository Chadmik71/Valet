Checked if more customers would slow things down or cost more data Fixed

What was asked
If we get 10,000 customers, or 100 people a day using the hands-free shopping service with photos, will that use a lot more internet data?
What we found and fixed
More customers alone is fine — that part was already built well. But photos (of shopping bags or cars) were being saved in a way that made each record much bigger than normal — like putting a full photo inside a text message instead of sending a link to it. If we start taking lots of photos every day, this would have slowly used up a lot more internet data. We fixed it: photos are now stored in their own separate place, and the record just keeps a small link to it. This keeps things fast and cheap no matter how many photos we take.
9 August 2026

Fixed old reports possibly missing information Fixed

What was asked
Fix the issue where reports for older dates might not show everything.
What we found and fixed
The app only keeps the most recent 2,000 cars ready to use on each device — older ones get quietly dropped to make room. If someone downloaded a report for an older date after we passed 2,000 total cars, it could have shown incomplete numbers with no warning. We fixed it: reports now double check they have everything for the dates you ask for, and if something's missing, they go get it before building the report. Nothing changed about how fast the everyday app feels.

9 August 2026

Fixed the printer not working for the first customer — for real this time (Zebra) Fixed

What was asked
Correction: the printer that had the problem is the Zebra one, not BIXOLON.
What we found and fixed
This same "cold start" problem had already been fixed for the Zebra printer once before, but it still happened again today. Checking with the user showed a clear pattern: the printer app was already open, and pressing print by hand worked straight away, first try. That tells us it wasn't the printer being switched off or the app not running — it was just the very first print request of the day having a one-off hiccup. So instead of trying to warm the printer up ahead of time (which clearly wasn't catching every case), the app now automatically tries again by itself, about a second later, if the very first print attempt fails — before showing any error to staff. Only if it fails twice in a row does it tell staff something's wrong. This should mean no more manual button presses for the first car of the day.

11 August 2026

Found and fixed the real reason internet data use crept up in recent weeks Watching

What was asked
Keep tracking how much internet data the app uses, and see if we can get back onto Supabase's free plan instead of the $25/month plan we're currently on.
What we found and fixed
One day this week used far more data than usual (about 385 MB). Digging deeper, the real story wasn't that one day — it's something that's been quietly happening for weeks: every time a staff phone or tablet wakes up, switches apps, or its connection drops and reconnects, the app was re-downloading the entire list of cars from scratch, even when almost nothing had changed. That happens a lot during a shift, so it added up fast. Fixed it so the app only downloads what's actually new or changed, plus a small check for anything deleted — cutting each of those re-downloads by roughly 80-100 times. Tested directly against the real data: about 2 MB down to about 28 KB per check. Still waiting to see a full day's real number before deciding whether to switch back to the free plan.
